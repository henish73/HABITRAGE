The new design looks right. Much of it isn't connected yet.

app/activity/page.tsx

app/layout.tsx

Hard-coded data shown as real

5
Home is frozen

"Needs you", the cash runway (it reuses the illustrative line from the mockup), the card wallet and "Latest activity" are static. Home will show "Today · Oct 16" forever, and the review count is always 14.

components/home/*.tsx
6
Wallet ignores your accounts

It fetches /api/accounts and then uses typed-in balances, limits, due dates and account numbers. Several numbers are wrong (TD ****1029 instead of ****7089). The APRs and the TransUnion score of 724 are invented, and Amex Green is shown at 20.99% APR, though it's a charge card with no interest rate.

app/wallet/page.tsx
7
Plan numbers are made up

Debt-free dates, "interest saved" and every budget figure are fixed values. The extra-payment slider changes nothing. If the bills request fails, it shows invented bills (Rent $1,900, Car Insurance). "AI Optimized" and "Synced 2 min ago" are only labels.

app/plan/page.tsx · components/layout/Topbar.tsx

Copilot safety

8
The confirmation card never appears

/api/chat never returns the proposedAction the card needs. If incomplete data arrives, the card shows placeholder details ("Uber, $5.82, TD Chequing") while Confirm deletes whatever transaction ID was sent. It also reports success without checking the response.

components/ai/FloatingAiWidget.tsx:185 · app/api/chat/route.ts
9
"Undo" is fake

There's no trash. The button shows "Transaction restored", and nothing comes back.

components/copilot/ProposedActionCard.tsx:40

Lost in the rewrite

app/activity/page.tsx:54

The analytics charts, adding or editing accounts, account balance charts, credit report upload and bill editing.

Mobile app

12
Always shows built-in sample data

The API now needs a login, so every request gets a 401 and the app silently falls back to its sample data. The server address 10.0.2.2 only works on the Android emulator.

apps/mobile/src/lib/api.ts
13
Design tokens aren't used

Neither app imports packages/design-tokens, so colors are still defined in several places.

apps/web/tailwind.config.ts · apps/mobile

Security

14
Logins can be forged

AUTH_SECRET isn't set, so session cookies are signed with the default key written in the source.

apps/web/src/lib/auth.ts:3 · .env.local
15
Any address with a "." skips the login check

The middleware lets through every path containing a dot.

apps/web/src/middleware.ts:13
16
No limit on passcode guesses

The login endpoint accepts unlimited attempts and compares the passcode with a plain string check.

app/api/auth/login/route.ts
Plan

Seven phases to finish 2.0

Each phase ends with a working app. Sizes assume one developer.

1Fix what's broken

about 1 day
  • A real Add bill form
  • Activity reads ?search= and ?tab=
  • Login page without the app shell
  • Copilot button above the phone tab bar
  • Close the transaction panel after a delete; show "$0.00" instead of "−$0.00"

2Connect real data

3–4 days
  • Home: "Needs you" from card usage, the review rule and the next bill; runway from a new /api/forecast; latest activity from the API
  • Wallet: from /api/accounts, with APR, statement day and due day stored per account
  • Credit score: only from an uploaded report, otherwise an empty state
  • Plan: payoff calculated from real balances and APRs, so the slider works; a budgets table with this month's real spending
  • Remove the fallback bills, "AI Optimized" and "Synced 2 min ago"

3Bring back lost features

4–5 days
  • Activity: server-side search and paging (or a virtual list) across all transactions; filters for date, account, category, amount and type; bulk recategorize or delete; CSV import; inline category edit; category management
  • Wallet: add, edit and delete accounts; account detail with a balance chart; credit report upload
  • Plan: an Insights tab with the old cash-flow, category and top-merchant charts

4Make Copilot actually safe

2 days
  • /api/chat returns a structured action with the real transaction and balance effect
  • No placeholder values on the card; check the response before showing success
  • Real trash (soft delete plus restore) so Undo works, or remove the button

5Mobile

5–7 days
  • Login screen; store the session token securely and send it with each request
  • Server address from config, so iPhones and real devices work
  • Replace sample data with the last real sync and an "Offline · last synced …" banner
  • Shared design tokens, the phone's dark mode, Face ID

6Security

half a day
  • Require AUTH_SECRET at startup
  • Close the "." bypass in the middleware
  • Limit login attempts; compare passcodes in constant time

7Keep it from breaking again

1–2 days
  • Feed design-tokens into the Tailwind config and the mobile theme
  • Tests for the forecast and payoff math
  • A browser smoke test for each page
  • Run next build before each commit, which would have caught the openAddBill error
