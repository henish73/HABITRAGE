Anomaly register

1. Security

S1Critical

Login bypass in Next.js 15.1.7 middleware

Confirmed locally. The audit lists 6 critical issues, including the middleware bypass, an RCE in the React flight protocol, and RCE through the image optimizer.

Upgrade Next.js to the latest 15.5.x (15.5.16 or newer), rebuild, and repeat the header test: it must return 401.
S2High

43 high and 26 moderate advisories

Mostly Next.js (denial of service, cache poisoning, SSRF) plus mobile build-tool packages (tar, @xmldom/xmldom, uuid, postcss).

Upgrade Next.js first (clears most), then update Expo packages and run pnpm audit --prod until no critical or high remain in what ships.
S3High

Unused packages ai and @google/genai

Nothing imports them, but they ship and add advisories (jsondiffpatch XSS).

Remove both from apps/web/package.json.
S4High

The login is checked in one place only

API routes trust the middleware completely, which is why S1 exposes everything.

Add a requireAuth() check at the top of every route handler (and the report page data calls), so a middleware failure can't open the API.
S5Medium

Weak, shared passcode

One 8-character passcode protects everything; no second factor. It was also used in test requests during this session.

Change it to a 12+ character passphrase before launch. Later: add a passkey or one-time code.
S6Medium

Sessions can't be revoked

A session token is valid for 30 days and logging out only clears the browser cookie. A leaked mobile token stays valid.

Add a session version in the signed token and a "sign out everywhere" button that bumps it; shorten mobile sessions to 7 days with renewal.
S7Medium

Login rate limit lives in memory

It resets on restart and depends on TRUSTED_PROXY_HOPS being right for your host.

Keep as is for one instance; document the setting (done) and alert on repeated 429s.
S8Low

No script CSP; fonts load from Google at runtime

Only framing and form directives are set. globals.css imports fonts from fonts.googleapis.com, which leaks visits to a third party and fails offline.

Self-host the fonts (next/font/local), then add a nonce-based CSP.

2. Ledger data

D1High

Transfers don't balance: 247 of 651 are unpaired, net +$26,996

Only 404 transfer rows pair up (same day, opposite amount, different account). "Transfers" mixes internal moves, card payments (106 "Credit Card Payments"), e-transfers to and from other people, and tuition. Totals, income and spending are all off because of it.

Split into "internal transfer" (paired, excluded from totals) and "e-transfer in / out" (counted as income or spending). Auto-pair on import.
D2High

20 rows where the type contradicts the sign

For example Uber on 2026-10-13: an "Inflow" of −$5.64 and an "Outflow" of +$5.64 (a refund pair), and Amazon refunds of +$68.13 and +$37.32 (Mar 2025) labelled Outflow. They show up as "positive outflows" in reports.

Add a data-health screen that lists these and fixes them in one click (or set type from the sign on import).
D3Medium

25 possible duplicate groups (40 extra rows)

The largest: eight identical "PAYPAL −$100" debits and eight "+$100" reversals on 2026-07-07 (CIBC eAdvantage). They may be real retries that net to zero, but they should be confirmed. Also 3× the same ATM fee on 2025-11-03.

Show duplicate groups in the data-health screen; make CSV import skip rows matching date + amount + description + account.
D4Medium

"Adjustments not to consider" is counted anyway

86 rows use a category that means "ignore me", but the dashboard charts and totals still include them (only budgets skip them).

Replace the category with an exclude_from_reports flag honoured by every total, chart and export.
D5Medium

The review queue is too big and never clears

654 rows (16%) match the rule, and there's no "reviewed" mark: a legitimate refund stays in the queue forever.

Add reviewed_at; the queue shows only unreviewed rows; "Mark reviewed" in bulk; tighten the rule.
D6Medium

CIBC eAdvantage Savings is $116.40 off its statement

The ledger rows add up to +$116.40 but the account balance is $0, so the app invented an opening balance of −$116.40. History is probably missing. Three accounts have had no activity for months (last: Jul 31, May 29, Apr 20).

Import the missing statement, or confirm and note the adjustment. Archive inactive accounts.
D7Medium

Cards have no APR or due date

All six cards lack an APR and five lack a due date, so the payoff planner and due dates run on estimates. Amex Green starts from a $5,562.58 balance that predates the imported rows.

Enter them (the account dialog now has the fields) from your statements.
D8Low

Messy categories and stale running balances

318 "Miscellaneous" rows, the typo "Tution Payments" (22 rows), "Credit Card Payments" overlapping Transfers, 2 zero-amount rows, and 2 accounts whose last running balance differs from the account balance.

Rename and merge categories; add rules that categorize by merchant on import; delete zero rows; recalculate running balances.

3. App bugs and made-up values

B1High

The cash forecast assumes your pay

/api/forecast hard-codes a $751.30 payday every 14 days from 2026-10-16 and $36.50 a day of spending. It will be wrong when your pay or schedule changes, and it also uses the server's date, which in Docker is UTC.

Detect recurring income from the ledger (or a Settings screen for pay amount and schedule); average real spending; send the client's date and timezone.
B2High

"Connect Bank" is a simulation

The button opens a fake Plaid screen. In production, users would think a bank is connected.

Remove it until a real integration exists, or label it clearly as "demo".
B3Medium

Sorting by amount ignores size

It sorts the signed value, so descending shows refunds first and the biggest expenses last. The October outflow report started with +$6.77 and +$5.64.

Sort by absolute amount (or offer "largest spend" and "largest income").
B4Medium

Hard-coded claims in the interface

"4,159 transactions" appears in Analytics, the AI prompt and the AI fallback reply; mobile "More" says "Synced with Supabase…4,158". Settings shows bill reminders as "Active" although no reminder job runs, and has a Supabase setup guide for something not in use.

Compute counts; remove or truthfully label the reminders and the Supabase section.
B5Medium

Old links lose their search

/transactions?search=x, /bills etc. redirect without keeping the query string.

Forward the query string in the redirect pages.
B6Medium

Two data stores, only partly kept in sync

If DATABASE_URL is set, only transactions and categories reach Postgres. Accounts, bills, credit reports, opening balances and the trash never do, so the two can disagree.

Pick one source of truth (see phase 4). Until then, don't set DATABASE_URL in production.
B7Medium

The ledger file will keep growing and blocking

3.26 MB today, saved pretty-printed (about 40% larger than needed) and fully rewritten on every change. About 2,100 new rows a year adds around 1.3 MB a year. AI chat history has no limit.

Save compact JSON, debounce writes, keep the last 100 chat messages, and move to a database in phase 4.
B8Low

Code quality

122 uses of any; the lint script has no ESLint installed so it can't run; the seed script holds sample bills, a sample credit report and a "Hello Henish" chat message.

Add ESLint with a strict config and fix any in API routes first; make the seed script opt-in.

4. Mobile app

M1Critical

It can't be built for the stores yet

app.json points to ./assets/icon.png, but there is no assets folder, and there is no eas.json.

Create the icon, adaptive icon and splash assets; add eas.json with development, preview and production profiles; set bundle IDs and versions.
M2High

Never run on a device or emulator

The new login, offline banner, Bills and Sign-out screens pass the type-check but haven't been tried. EXPO_PUBLIC_API_URL isn't set, so real phones can't reach a server.

Run on an Android emulator and a real phone against a staging server; fix what breaks; set the API URL per build profile.
M3Medium

No biometric lock; push notifications do nothing

Anyone holding an unlocked phone sees balances (they are blurred by default, but one tap reveals them). The app asks for notification permission but no server sends any.

Add Face ID / fingerprint on app open (expo-local-authentication); either build bill reminders or stop asking for the permission.
M4Medium

Mobile has fewer features than web

Transactions on mobile has no date range, filters, export or bulk actions, and no way to add a transaction.

Add a date range and filter sheet, search across all rows, and "add transaction" after the web fixes are shipped.

5. Operations and quality

O1High

Docker image has never been built

Docker Desktop was off. The Dockerfile was repaired this session but is untested, including the standalone output path in a monorepo.

Build it, run it with a volume, log in, add and delete a transaction, restart, and confirm the data survived.
O2High

No backups, monitoring or alerts

The whole ledger is one file. There is no scheduled copy, no error tracking, no uptime check.

Nightly encrypted copy off the server (keep 30 days) and a restore test; Sentry (or similar) for errors; an uptime check on /api/health.
O3Medium

No CI and no browser tests

Nothing runs the tests, type-check, build or audit on a change, and no test clicks through the real app.

GitHub Actions: install, typecheck, test, build, pnpm audit. Add Playwright smoke tests for login, Activity filters, export and bulk actions.
O4Medium

Must run as exactly one instance

The ledger lives in memory and one file; two instances would overwrite each other. The app also isn't covered by a staging environment.

Max instances = 1 (documented in DEPLOY.md); stand up a staging copy with test data.
O5Low

Everything is still uncommitted

This session's work (about 50 files) and the earlier changes aren't in git, and there's no remote.

Commit in logical pieces, create a private remote, protect the main branch.
The plan

Phases to production

Effort assumes one developer. Phases 0 and 1 gate going live; the rest can follow in order.

P0Close the security holes (blocks launch)

1 day
  • Upgrade Next.js to the latest 15.5.x; rebuild; run all tests
  • Add requireAuth() to every API route handler and the report data calls
  • Remove the unused ai and @google/genai packages
  • Change the passcode to a 12+ character passphrase; set AUTH_SECRET in your host's secret manager
  • Re-test the bypass header on the staging build, and run pnpm audit --prod
Done when: the x-middleware-subrequest request returns 401 for API and pages, and the audit shows no critical advisories in the web app.

P1Make the numbers trustworthy (blocks launch)

3–4 days
  • Transfers: pair internal transfers and exclude them from totals; classify e-transfers in/out as income or spending (D1)
  • Data-health screen: wrong type vs sign, possible duplicates, zero amounts, unreviewed items, with one-click fixes (D2, D3, D8)
  • exclude_from_reports flag honoured by totals, charts, budgets and export (D4)
  • "Reviewed" flag and bulk "Mark reviewed" so the queue empties (D5)
  • Fix sorting by amount to use size (B3)
  • Forecast from your real data: detect pay from the ledger or add a Settings screen; use real average spending (B1)
  • You enter each card's APR and due date; resolve the $116.40 gap (D6, D7)
Done when: the transfer net is about zero, the review queue is under 50 and clearable, the forecast uses your actual pay, and totals match a statement for one full month.

P2Remove anything fake or misleading

1–2 days
  • Remove or label the simulated Connect Bank (B2)
  • Replace hard-coded counts and the "Active" reminder claims; drop the Supabase guide (B4)
  • Forward the query string in old-route redirects (B5)
  • Make the seed script opt-in and free of personal sample data (B8)
  • Self-host fonts (S8)
Done when: a search for "4,159", "Supabase" and "simulate" in the source finds nothing that reaches users.

P3Deploy to staging and prove it

2–3 days
  • Build and run the Docker image with a volume; add, edit, delete, restart, confirm data persists (O1)
  • CI on every push: install, typecheck, test, build, audit (O3)
  • Playwright smoke tests: login, filter by date, export CSV, report page, bulk type change, undo delete
  • Backups: nightly encrypted copy, 30 days kept, one restore rehearsal (O2)
  • Monitoring: error tracking and an uptime check on /api/health; alert on repeated login failures
  • HTTPS with your domain; max one instance (O4)
Done when: a fresh deploy from CI works, a restored backup opens correctly, and an error you cause on purpose shows up in monitoring.

P4Mobile release

5–7 days
  • Assets and build: icon, adaptive icon, splash, eas.json, bundle IDs, versions (M1)
  • Test on a real phone against staging: login, offline banner, bills, sign-out (M2)
  • Biometric lock on open; decide on push notifications (M3)
  • Feature parity: date range, filters, search across all rows, add transaction (M4)
  • Distribute through TestFlight / an internal Android track first
Done when: a preview build installs on your phone, shows live data, locks with Face ID, and works offline with the banner.

P5Choose the long-term database

4–6 days
  • Decide: stay on the single file (one user, single instance) or make Postgres the only source of truth
  • If Postgres: migrate accounts, bills, reports, opening balances and trash; remove the JSON path; run the migration on a copy first (B6)
  • If staying on the file: compact saves, debounced writes, chat-history cap (B7)
  • Sessions you can revoke and a "sign out everywhere" button (S6)
  • Second factor (passkey or one-time code) (S5)
Done when: there is exactly one store of record, and a lost server can be rebuilt from a backup in under 30 minutes.
